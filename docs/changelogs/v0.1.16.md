## Breaking changes

- After one `provider-credential-set` apply, the secret store carries a record an earlier acps cannot read, so rolling back past this release needs the namespace cleared first.
- `acps extensions status --json` reports a managed-state namespace's providers as `provider_ids` instead of `provider_id`.

## Features

- A managed-state namespace declared with `capability = "provider-credential"` also takes `{kind: "provider-credential-set", selections: [...]}`: credentials for 1 to 16 providers that become the Agent's active provider set in the same call. The default slot stays while its provider is in the set and otherwise moves to the first, with its model cleared; a subagent provider outside the set is cleared. The answer's `agent_environment` says whether the running Agent holds the applied env (`live`) or must restart (`restart_required`). Advertised as the `managed-provider-credential-set` feature.
- The two credential kinds share a namespace's record: a one-selection set replays a `provider-credential` body of the same selection as `noop`, and a `provider-credential` body after a set removes the set's other providers from the store and from the active set, which its selection takes over when nothing else remains.
- A credential apply through `POST /v1/admin/extensions/{name}/apply` invalidates the model catalog only for providers whose credential was added, removed or changed, and a credential applied again with the same values keeps its stored revision.
