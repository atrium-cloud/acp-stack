## Breaking changes

- After one `provider-credential-set` apply, the secret store carries a record an earlier acps cannot read, so rolling back past this release needs the namespace cleared first.
- `acps extensions status --json` reports a managed-state namespace's providers as `provider_ids` instead of `provider_id`.

## Features

- A managed-state namespace declared with `capability = "provider-credential"` also takes `{kind: "provider-credential-set", selections: [...]}`: credentials for 1 to 16 providers that become the Agent's active provider set in the same call. The default slot stays while its provider is in the set and otherwise moves to the first, with its model cleared; a subagent provider outside the set is cleared. The answer's `agent_environment` says whether the running Agent holds the applied env (`live`) or must restart (`restart_required`). Advertised as the `managed-provider-credential-set` feature.
- The two credential kinds share a namespace's record: a one-selection set replays a `provider-credential` body of the same selection as `noop`, and a `provider-credential` body after a set removes the set's other providers from the store and from the active set, which its selection takes over when nothing else remains.
- A credential apply through `POST /v1/admin/extensions/{name}/apply` invalidates the model catalog only for providers whose credential was added, removed or changed, and a credential applied again with the same values keeps its stored revision.
- Pi's endpoint probe and `PI_ACP_HIDE_PROVIDERS` cover every active provider's row, each with its own key reference, instead of only the default slot's. Every Agent launch, a crash respawn included, rewrites Pi's settings from the verdicts its hide list reads, and a credential apply leaves a running adapter's settings alone. A default slot with no model on a row with several endpoints runs on the row's first endpoint not hidden, which Pi's `defaultProvider` names.
- An adapter advertising `agentCapabilities._meta.acpStack.launchEnv` takes a `provider-credential-set` apply without an Agent restart: after a probe the bridge sends `_acpStack/launch_env` with the set's provider variables, the provider names it leaves out and the hide list, Pi's settings follow once the adapter answers, and the apply answers `agent_environment: "live"`. An adapter without it, a custom provider slot, a failed request, or no answer within 10 seconds answers `restart_required`. An `on-crash` respawn after a push launches with the pushed env, and its hide list covers the pushed set; one pending while an apply lands launches with the applied env.
- `POST /v1/sessions/{id}/detach` closes the agent-side session as `DELETE /v1/sessions/{id}` does, cancelling its live prompt, but leaves the row `available` so the next prompt re-attaches it. Subagent rows stay and lose their live state. The demotion records a `session.available` event with reason `detached`. An adapter that advertises neither `session/resume` nor `session/load` answers `501 session.reattach_unsupported` and keeps the session. `DELETE /v1/sessions/{id}` sends `session/close` only for a session the running adapter holds.
