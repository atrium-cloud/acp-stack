This release moves artifact distribution to the Atrium releases service. The tag-triggered release workflow still builds the same matrix, but publication now happens against the service over GitHub OIDC; the GitHub Release carries notes only. There is no operator-facing behavior change to acp-stack itself.

## Release pipeline

- Pushing a stable `vX.Y.Z` tag triggers the release workflow, which builds the release matrix and publishes it to the Atrium releases service. The job runs with `id-token: write` and authenticates with a GitHub OIDC token; the service verifies the workflow identity — repository, workflow path, and tag ref — against its publisher trust policy, so no long-lived publishing credentials exist to rotate or leak.
- Uploads are checksum- and size-bound: the service issues presigned URLs for each manifest entry and finalizes the release only after every stored object matches its declared size and SHA-256. A release that fails verification is never visible to downloaders.
- Publication is idempotent. An identical retry returns the existing session, and finalizing an already-published session returns the existing release, so re-running a failed workflow job is the supported retry path. A `workflow_dispatch` run must use the tag as the run ref or publication is rejected.

## Maintainer tooling

- `scripts/release.sh [patch|minor|major|X.Y.Z] [--dry-run] [--push]` is the release entrypoint: it advances the workspace version, pairs it with this changelog, and creates the release commit and tag locally. Compilation and publication remain in GitHub Actions; without `--push` nothing leaves the maintainer's machine.
