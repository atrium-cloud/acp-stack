This release makes agent capability handling probe-first and degrade-gracefully, adds Hermes Agent as a supported harness, introduces live provider model catalogs, and lets session routes lazily start a stopped agent. It also reworks the release pipeline around nightly tags and bumps the ACP SDK to 1.3.0.

## Capability probing and gating

- `acps init` gains a handshake-only capability probe: after install it spawns the agent, completes ACP `initialize`, persists the capability snapshot, and terminates without creating a session, so `GET /v1/agent/capabilities` and `acps agent status` answer before the first real start. A failed probe records `probe_status: "unavailable"` and never fails init. The static `supports_mcp` registry flag is removed; MCP support now comes solely from the live advertisement, and MCP prompting moved into its own post-install step that only appears when the probe advertised MCP support.
- Configured features the agent does not advertise are no longer errors. They stay in config, are skipped at session time, and are reported as ignored: terminal init prints one `ignored:` line per feature, the handoff payload carries `ignored_features`, and session create returns an `ignored` array plus a warn-level `session.capability_ignored` event.
- An MCP server whose transport the agent does not advertise (`mcpCapabilities.http` / `mcpCapabilities.sse`) no longer fails session creation with `agent.unsupported_capability`. Create, load, resume, and fork proceed with the remaining servers, each skip is recorded as a warn-level `mcp.session_skipped` session event, and the attached-servers record reflects what was actually attached. An unclassifiable transport remains a hard failure.
- New route `POST /v1/sessions/{id}/delete` forwards ACP `session/delete` and hard-deletes the local session row with its prompts and per-session events, gated on the new `sessionCapabilities.delete` capability (501 `agent.unsupported_capability` when unadvertised). The route is idempotent — an unknown or already-deleted id returns `deleted: false` without dialing the agent — and pending ACP-source permissions are canceled with reason `session-deleted`. `DELETE /v1/sessions/{id}` keeps its history-preserving close semantics.

## Hermes Agent

- Hermes Agent (`hermes acp`) is a supported native harness, with a registry entry, shell install path, and a headless provisioner that writes only the non-secret `model` block of `~/.hermes/config.yaml` while the API key stays in the encrypted store and reaches the process via `[agent].env`. `openai` and `openrouter` gain Hermes in their provider mappings; its OAuth-only providers are deliberately unmapped.
- Support is aligned with Hermes' pre-1.0 ACP surface: model ids are accepted verbatim without ACP discovery, configured MCP servers are recorded as ignored features, and the bridge injects the process-only `HERMES_ACP_SKIP_CONFIGURED_MCP=1` so servers from Hermes' own config do not leak into managed sessions (declaring that variable in `[agent].env` is rejected). `GET /v1/models` no longer errors for explicit-model agents missing an ACP model advertisement — it serves an empty list alongside `catalog_error`.

## Sessions and permissions

- Session routes that need the bridge — create, load, resume, fork, prompt — now lazily start the configured agent when the supervisor is stopped, so a host that only ran `acps init` and `acps serve` no longer answers `agent.not_running` until an explicit `POST /v1/agent/start`. A request arriving during an in-flight start waits for readiness (up to 30s) instead of spawning a second agent; `restart = "never"` targets and stopping/updating supervisors still return `agent.not_running`.
- A pending permission request no longer outlives its mediated command: terminal command states (cancel, spawn/start/persistence failure, teardown, startup reconcile) cancel the pending permission in the same transaction with a machine-readable `reason` such as `command-canceled` or `command-reconciled`. Decision events now carry `source`, `subject_id`, and `command_id`, and deciding an already-terminal request returns 409 `permission.invalid_transition` — "already settled", not retryable.

## Models and provider catalogs

- New provider model catalog subsystem: providers may declare `models_url` in `data/providers.toml`, and the runtime fetches the OpenAI-compatible model list with the stored key, caching it at `~/.config/acp-stack/provider-models.json` (300s TTL, 30s failure backoff; failures never overwrite a usable cache). `GET /v1/models` now returns `{ "agent_id", "source", "models", "modes", "catalog_error"? }` with `source` of `provider_catalog` or `acp_advertised`, and Claude Code's `settings.json` gains a managed `availableModels` array built from the catalog so profiled providers advertise real selectable models.
- The codex non-OpenAI init lane lists models from the live provider catalog instead of codex-acp's bundled OpenAI presets; when no catalog is available the model step is skipped with a hint to rerun with `acps init --model <value>` rather than surfacing misleading presets.
- Third-party Claude Code provider profiles are refreshed (DeepSeek `deepseek-v4-pro[1m]`, Moonshot `kimi-k3[1m]`, new `moonshotai-cn` and `kimi-coding-plan` profiles, MiniMax auto-compact raise, Z.AI nonessential-traffic opt-out), and the Codex adapter moves to `@agentclientprotocol/codex-acp` as npm-only. Codex with OpenRouter now authenticates via a command-based `auth` block against `https://openrouter.ai/api/v1` so its model catalog refreshes with correct metadata.
- `acps agent test` is non-interactive-safe: testflight auto-approves permission requests by selecting the first allow option and never a reject option, via the bridge's new `AcpPermissionPolicy`.

## Init and installs

- Installed agent binaries are gated on a real executable format (ELF, Mach-O, or shebang) and a `--version` spawn probe that judges spawnability only, catching stubs left by blocked npm postinstalls and wrong-architecture downloads at install time instead of as ENOEXEC at first agent spawn. When `expected_sha256` is declared the probe runs only after the pin check, so a binary failing the operator's pin is never executed. Failing binaries read as absent and are reinstalled; the new error code is `agent.installer_binary_unrunnable`.
- npm-based agent installs pass `--allow-scripts=<package>` so the installed package's lifecycle scripts run under npm 12, which otherwise silently skips them and links a stub bin that passes the install check. Only the installed package is approved; transitive dependency scripts keep npm's default skip-and-report behavior.
- `scope = "system"` dependency installs escalate through passwordless `sudo -n` when the daemon is not root, never prompting for a password or tty. When escalation is unavailable, `acps init --deps-apply` records the action as `privilege_required` and continues (skips surface in status, health, and installer history), while `acps deps apply` prints the manual `sudo` commands and exits non-zero. Genuine action failures still fail both paths.
- Managed skills are symlinked from the install dir into each harness's discovery dir (for Claude Code, `~/.agents/skills` into `~/.claude/skills`), refreshed on init skill install and `acps agent switch`. The mirror is one-way: only symlinks into the install dir are managed, dangling links are pruned, and a real file at a link path is left alone and reported as a conflict. `POST /v1/agent/switch` gains a `skills_link` report.
- Successful text-mode init runs end with a `next:` hint pointing at `acps serve` and `acps sessions new`, and the run is marked succeeded before the key handover is printed so a state-store failure surfaces as a failed run rather than a success followed by a nonzero exit.
- The native update probe report distinguishes "did not advertise update or upgrade" from "could not be probed", appends per-probe status detail, and retries once after 200ms on transient spawn errors.

## Releases and updates

- `scripts/release.sh` now defaults to nightly releases: it tags `main` HEAD as `vX.Y.Z.N` with no version commit or changelog and publishes a GitHub prerelease. `--regular` and `--major` keep the changelog-and-commit flow. Nightly artifacts and the release manifest carry the 4-part version while the binary still reports the 3-part Cargo.toml version; `acps update` never offers nightlies automatically — they install via `install.sh --version vX.Y.Z.N` or an explicit `acps update --version`.
- The self-updater replaces the `semver` crate with an in-house `ReleaseVersion` parser that orders nightly versions as `0.1.1 < 0.1.1.1 < 0.1.2`.

## Dependencies

- `agent-client-protocol` bumped from 1.2.0 to 1.3.0 (with `agent-client-protocol-derive`; the transitive `agent-client-protocol-schema` dependency stays at 1.4.0). The upstream Rust SDK now lives at `agentclientprotocol/rust-sdk`; 1.3.0 brings correct incoming-EOF handling, bounded stderr capture, and killing the agent's whole process group when the child guard drops.
