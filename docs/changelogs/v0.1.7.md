This release adds secret-reference template interpolation in config values, moves hosted init environment configuration into the session-create request, and fixes init tty hangs and hosted key-handover wedges.

## Config

- Value positions (HTTP MCP header `value`, stdio MCP `env` entries, and `[agent].env` entries) now accept `${SECRET_REF}` templates in addition to whole-value refs, so one secret can be composed into several values (`Bearer ${KEY}`, `postgres://user:${DB_PASS}@host/db`). A template must contain at least one ref — pure literals are rejected so plaintext credentials cannot be pasted into config — and the pasted-credential screening also runs over template literals, including concatenated across `${}` boundaries.
- HTTP MCP server URLs may now be plain http toward a loopback host (a local relay endpoint); https is still required everywhere else, and URLs carrying userinfo credentials are rejected.
- A single invalid MCP server declaration no longer fails daemon startup: it is skipped with a startup warning while declaration and config-write paths still reject it.

## Hosted init

- `POST /v1/init/sessions` now accepts the full environment configuration up-front — MCP presets/stdio/http declarations, skills selection, dependency install records, browser-use, and data sources — replacing the interactive environment wizard, which is never streamed to hosted clients. Secret values are still never carried in the request body: refs missing from the store are collected over the prompt stream as optional password inputs, and a skipped ref surfaces later through MCP health or workspace materialization instead of failing the session.
- Hosted init now always rotates existing keys, so the WebSocket `result` frame always carries plaintext `session_key` and `admin_key`. Previously a run over pre-existing state took the key-preserving path and left the backend permanently unable to obtain credentials.
- An init failure before key handover no longer dies with an unreadable port: the session parks as `errored`, the typed error is retrievable via the status route, the reconnect `hello` frame, and the new `replay_error` frame, and `ack_error` releases the server (exit non-zero). An unacknowledged error expires after a 2-minute grace regardless of `--idle-timeout` and connected clients. A failure after key handover still delivers a `"status": "failed"` result frame with the keys through the normal result/ack path.
- Create-route validation is stricter: unknown request fields are rejected, and MCP secret-value positions are validated in full at the boundary (pasted-credential screening, ref-name and template syntax, the exactly-one-of `value_ref`/`value` header rule) as a `400` instead of failing in-session.

## Init and installs

- Installer subprocesses are detached into a new session with no controlling terminal and run with non-interactive environment hints (`CI`, `NONINTERACTIVE`, `DEBIAN_FRONTEND`, `GIT_TERMINAL_PROMPT`) pinned, so a vendor installer that probes `/dev/tty` to prompt ("existing install detected, overwrite?") takes its non-interactive branch instead of hanging init until the timeout.
- `acps init --rotate-keys` regenerates both API keys in place over existing verifier rows and prints the new plaintexts once; the retired keys stop verifying immediately, and a running daemon must be restarted to accept the rotated pair. Handoff JSON reports rotated keys under `generated_keys`.
- On runs that create a config (or `--resume`), interactive init offers masked entry for declared MCP and S3 data-source secret refs missing from the store.
- `--data-from` against an existing config is now rejected (edit `[[workspace.data_sources]]` instead); it only ever applied to a new starter config.

## Dependencies

- `quinn-proto` bumped from 0.11.14 to 0.11.16.
