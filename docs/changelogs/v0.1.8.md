This release fixes an opencode install path that could silently succeed on a stale binary, raises the ACP `initialize` timeout for cold first launches, and folds Claude Code provider profiles into `providers.toml`.

## Fixes

- The opencode installer script is now fetched to a variable before being piped to `bash`, and an empty body is treated as a failed fetch. Previously a `curl` failure under `curl -fsSL ... | bash` ran an empty script that exited 0, so a stale `opencode` binary left by an earlier run passed the post-install check — hiding the failure and skipping the npm fallback, which is the path that survives GitHub API rate limits.
- The ACP `initialize` timeout is raised from 15s to 60s. A warm agent handshakes in milliseconds, but the first launch on a freshly provisioned host pays for cold page cache, runtime warmup, and the agent's own first-run setup; 15s was tight enough that hosted init failed `provider_configure` on real hosts. The deadline still catches a wedged or incompatible agent.

## Config

- Claude Code provider profiles moved from the hardcoded `claude_code_provider_profiles` Rust module and `data/claude_code_providers.toml` into `data/providers.toml` as a per-provider `claude_code` sub-profile. Profiles are validated at load: a provider that declares a Claude Code profile must list `claude-code` among its supported agents, `base_url` must be an HTTP(S) URL, and model names are token-validated. Omitted companion/optional env-var lists fall back to the provider-level and `env_vars.toml` lists; an explicitly empty list is honored. No user-facing config change.
