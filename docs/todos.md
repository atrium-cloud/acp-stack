## Delivered

- [x] Stamp the session id on ACP-source permission decision events (2026-09-18). The decision-event enrichment already reads the request row to attach `source` and `subject_id`, so it now returns the ACP-source subject as the session scope and the append writes through the session-scoped path. Decisions land in the per-session event log, reach the `sessions.{id}` topic live, and replay on reload. Command-source requests belong to a command rather than a session and stay unscoped, and `permission.created` stays unscoped as well. Surfaced from webui.
- [x] Put the real cause on prompt-failure events (2026-09-18). `prompt.errored`, `prompt.inference_failed`, and `prompt.stalled` payloads gained a `cause` field holding the same text the prompt row's `error_message` carries: the error's public message for the supervisor's two kinds, the sweeper's stall reason for the third. The public message is what the scrub already keeps free of local paths, I/O text, and subprocess output, so a transcript distinguishes a rate limit from a crashed subprocess without a second read and without a new sanitizer. The existing payload fields and the static `message` column are unchanged. Surfaced from webui.
- [x] Link client terminals to the session's event stream (2026-09-18). A `commands` row now records the ACP terminal id it ran (migration 026), minted before the row is inserted so a terminal that exits immediately still names itself. Finalizing a terminal appends one session-scoped `terminal.finished` event carrying the terminal id, command id, cwd, status, exit status, signal, duration, and an 8 KiB output tail cut at a UTF-8 boundary; spawn and start failures record it too, so a tool call the agent announced always resolves. Raw stdout/stderr chunks stay unscoped on the command log, which still serves the untrimmed stream by command id. No adapter is observed using client terminals yet: OpenCode and Pi complete shell work through their own built-in tools, and the deterministic coverage is the placebo agent. Surfaced from webui.
- [x] Record the accepted user prompt as a durable session event (2026-09-18). The supervisor writes the prompt as `session.update` rows in ACP's own `user_message_chunk` shape, one per content block, under the same state guard as the `prompts` insert and before the ACP request goes out, so a transcript replayed from the log opens on the user's turn. Rows carry source `system` rather than `acp`, which keeps them out of the stream-start probe in the multi-session status view; the chunk's `messageId` is the prompt's message id and `_meta.acpStack.promptId` names the prompt row, so a client that rendered the prompt optimistically can match its local entry against the durable one. Sealing on an Enhanced Computer needed no change here: the daemon's broker seals every event row served by the session-events and snapshot routes by row shape, not by kind. Surfaced from webui.
